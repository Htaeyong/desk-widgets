# 스티키 노트 + 할 일 통합 설계 (#110)

> 상태: **구현됨(#111), 새 위젯 "할 일 노트"(id `todonote`) 0.0.1, Gitea 전용**. 사용자가 12장 B~K를 추천안대로 정했고, **결정 A는 사용자 결정으로 바뀌었습니다**(2026-10-25, 정책과 합의사항 todonote 행): 스티키 노트에 넣지 않고 스티키 노트를 바탕으로 한 **별도 위젯 "할 일 노트"**를 만들며, 스티키 노트는 그대로 유지·배포합니다. 이 문서의 "스티키 노트"·`memo`는 할 일 기능에 관해서는 **할 일 노트**·`todonote`로 읽습니다. 할 일 목록 동결(9장)은 **미뤘습니다**(할 일 노트 정식 배포 때 스티키 노트 동결 여부와 함께 결정). 설계와 달라진 점은 [13장](#13-구현에서-달라진-점-111), 사용법은 [할 일 노트](todonote.md).

## 0. 한 줄 요약

**노트는 그대로 노트**이고, 목표 날짜를 걸면 그 노트가 **할 일**이 됩니다. 날짜·반복·완료 정보는 노트 파일 맨 위 머리말(front matter)에 몇 줄로 들어가므로 노트는 계속 "문서 폴더의 Markdown 파일 하나"입니다. 알림 카드·다시 알림·반복·캘린더 마감 표시·두레이/메일에서 추가는 할 일 목록 위젯에 있던 것을 노트 위젯으로 옮깁니다. 할 일 목록 위젯은 1.1.0에서 멈춥니다(동결).

| 고정된 사용자 결정 | 이 설계에서의 모습 |
|---|---|
| 1. 할 일 목록 위젯은 지금 공개 버전 유지, 새 버전 없음, 안내 문구 | 1.1.0 **동결 위젯**(9장). 소스 버전도 1.1.0으로 되돌리고 같은 버전 정책의 예외로 둠 |
| 2. 두레이·메일 "할 일로 추가"는 노트를 만듦 | 내용이 든 노트 파일을 만듦(8.2) |
| 3. 완료 후 자동 삭제 기본 30일, 기간 설정, "삭제 안 함" | `완료` 폴더 → 기간 뒤 Windows 휴지통(6장). 반복 노트는 제외 |
| 4. 목표 날짜를 걸 때만 할 일, Todoist처럼 입력 | 띠의 ⏰ 버튼·`/` 명령·첫 줄 제안 + 할 일 위젯 해석기 확장(2.2, 4장) |

## 1. 용어

| 말 | 뜻 |
|---|---|
| 노트 | 지금의 스티키 노트. 머리말에 `due`가 없으면 그냥 노트 |
| 할 일 노트 | 머리말에 올바른 `due`가 있는 노트 |
| 반복 노트 | `due`와 올바른 `repeat`이 있는 노트 |
| 완료 노트 | `completed`가 있는(반복이 아닌) 노트. `완료` 폴더로 옮겨짐 |
| 마감 상태 | 지남 / 오늘 / 곧(내일~7일) / 나중 / 완료 |

## 2. 화면 (UX)

원칙: **노트 창은 작고 노트처럼.** 날짜가 없는 노트는 지금과 한 칸도 다르지 않습니다(⏰ 버튼 하나만 띠에 추가, 마우스를 올렸을 때만 진하게).

### 2.1 노트 창

날짜 없는 노트(지금과 같음, ⏰만 추가):

```
┌────────────────────────────────┐
│ 장보기              ⏰ + Aa ▾ × │  ← ⏰는 마우스를 올렸을 때만 진하게
├────────────────────────────────┤
│ - [ ] 우유                      │
│ - [x] 달걀                      │
└────────────────────────────────┘
```

할 일 노트: 띠 바로 아래 **얇은 마감 줄**(높이 18px) 하나가 생깁니다. 마감 줄 = 마감 칩 + 반복 표시 + **완료** 버튼.

```
┌────────────────────────────────┐
│ 월간 보고              + Aa ▾ × │
│ ⏰ 오늘 15:00 · ↻ 매월 1일   ✓ 완료│  ← 마감 줄. 칩을 누르면 날짜 편집
├────────────────────────────────┤
│ # 절차                          │
│ - [ ] 매출 집계 시트 열기         │
│ - [ ] 지난달과 비교               │
│ [[보고 양식]] 복사해서 제출         │
└────────────────────────────────┘
```

마감 칩의 모양(색은 노트 색 7가지 위에서도 읽히도록 칩 테두리와 글자색만 바꿈):

| 상태 | 칩 글자 | 표시 |
|---|---|---|
| 지남 | `지남 · 10/28 (어제)`, 시각이 있으면 `지남 · 2시간` | 빨간 글자 + 빨간 테두리, 창 왼쪽 가장자리에 3px 빨간 띠 |
| 오늘 | `오늘 15:00` / `오늘` | 주황 글자 |
| 곧 | `내일 09:00`, `금 (11/1)` | 기본 글자색 |
| 나중 | `11/30` | 흐린 글자 |
| 접힌 창 | 띠 오른쪽에 작은 점(지남 빨강 / 오늘 주황) | 접어 둬도 상태가 보임 |

**완료** 버튼(✓ 완료, Ctrl+Enter)을 누르면:

- **반복 없음**: 창이 0.3초 흐려지며 닫히고, 노트는 `완료` 폴더로 옮겨집니다. 화면 아래 엔진 공용 알림 대신 **목록 창이 열려 있으면 목록에**, 아니면 짧은 알림 카드 하나("월간 보고 완료 · 되돌리기", 8초)로 되돌리기를 줍니다.
- **반복 있음**: 다음 날짜로 넘어가고(5장), 체크 목록을 비우는 설정이면 비우고, 창은 닫힙니다. 다음 날짜(알림 시각)가 되면 **창이 같은 자리에 다시 열리고** 알림 카드가 뜹니다(설정 "반복 노트는 때가 되면 창 다시 열기", 기본 켬). 목록의 **할 일** 보기에는 "11/1 (금) 예정"으로 남습니다.

오른쪽 클릭 메뉴에 **날짜 정하기…**, **반복…**, **완료**, **날짜 지우기(노트로 되돌리기)**가 더해집니다.

### 2.2 날짜 빠르게 걸기

세 가지 길이 있고, 모두 같은 해석기(4장)와 같은 날짜 창을 씁니다.

**① ⏰ 버튼 / 마감 칩 / Ctrl+Shift+D → 날짜 창(작은 팝오버)**

```
┌──────────────────────────────┐
│ 언제?  [다음 주 월요일 오후 3시 ]│  ← 바로 입력, Enter로 적용
│ → 11월 2일 (월) 오후 3:00       │  ← 입력하는 대로 해석 결과 미리 보기
│ [오늘] [내일] [다음 주 월] [주말] │
│ ↻ 반복  [없음 ▾]                │  ← 없음·매일·평일·매주 (요일)·매월 (날)·매년·완료 후…
│ 🔔 알림 [마감 시각 ▾]           │  ← 마감 시각·10분 전·1시간 전·전날 18시·끄기
│ [달력에서 고르기]   [지우기][확인]│
└──────────────────────────────┘
```

- 해석할 수 없으면 미리 보기 줄이 "알 수 없는 날짜"(빨강)이고 Enter가 적용하지 않습니다.
- 반복 문구를 직접 쳐도 됩니다(`매월 1일 오전 9시` → 반복 칸이 따라 바뀜).
- **달력에서 고르기**는 같은 팝오버 안에 작은 월 달력(7×6)을 펼칩니다. 노트 창이 작으면 팝오버만 창 밖으로 나가지 않도록 창을 잠깐 넓히지 않고 **창 안에서 스크롤**합니다(창 크기는 바꾸지 않음).

**② `/` 명령 (본문에서)**

줄 맨 앞이나 빈칸 뒤에서 `/`를 치면 작은 명령 목록이 뜹니다(`[[`와 같은 방식, ↑↓·Enter·Esc).

```
/내일 3시▏
 ⏰ 날짜: 10/26 (월) 오후 3:00   ← 해석되면 맨 위에 바로 적용 항목
 ↻ 반복…
 ✓ 완료
 ✕ 날짜 지우기
```

- `/` 뒤에 날짜 문구를 이어 치면 맨 위 항목이 해석 결과로 바뀌고 Enter로 적용합니다. 적용하면 본문에 친 `/내일 3시`는 지워집니다.
- `a/b`, `http://`처럼 글자 뒤의 `/`는 명령이 아닙니다. 코드·코드 블록 안에서도 뜨지 않습니다.

**③ 첫 줄 제안 (Todoist식, 자동 적용은 안 함)**

새 노트의 첫 줄이 날짜 문구로 끝나면(`보고서 제출 금요일 5시`) 첫 줄 끝에 흐린 제안 칩 `⏰ 금 17:00?`이 보이고, **Tab** 또는 칩 클릭으로 적용합니다. 적용하면 첫 줄(=노트 이름)에서 날짜 문구가 빠집니다. 메모에 "회의 3시"처럼 쓴 것이 저절로 할 일이 되면 안 되므로 **자동 적용하지 않습니다**.

### 2.3 알림 카드

엔진 일반 카드(API 1.2)의 버튼은 3개까지라 정확히 맞습니다. 다시 알림 시간 고르기는 카드 메뉴(API 1.4)로.

```
┌ ✓ 할 일 ────────────────────── ⋯ ┐
│ 월간 보고                         │
│ 오늘 15:00 · ↻ 매월 1일           │
│ [완료]  [10분 뒤]  [노트 열기]      │
└──────────────────────────────────┘
  ⋯ 메뉴: 다시 알림 10분 · 30분 · 1시간 · 오늘 저녁(18시) · 내일 아침(9시)
```

| 버튼 | 동작 |
|---|---|
| 완료 | 노트 창의 완료와 같음(반복이면 다음 날짜로) |
| N분 뒤 | 설정의 다시 알림 간격(기본 10분, 1~120분). 파일은 바꾸지 않음(2.5·3.4) |
| 노트 열기 | 그 노트 창을 열고 앞으로 가져옴(닫혀 있었으면 저장된 자리에) |

- `sticky`(누를 때까지 남음), 소리 있음, `tag: memo-<id>`(같은 노트의 카드는 하나만).
- 종일 할 일은 그날 **오전 9시**(설정 "종일 할 일 알림 시각", 끌 수 있음)에 알립니다. 지금 할 일 위젯은 종일 할 일을 알리지 않지만, 노트에서는 날짜만 거는 일이 대부분이라 알리는 쪽을 추천합니다.
- PC가 꺼져 있던 동안 지난 알림은 12시간 안의 것만 뒤늦게 띄웁니다(할 일 위젯과 같음). 그보다 오래 지난 할 일은 카드 대신 시작 때 **요약 카드 한 장**("지난 할 일 3개 · 목록 보기")을 띄웁니다.

### 2.4 노트 목록

탭을 지금 2개(노트·보관함)에서 4개로:

```
┌ 노트 목록 ───────────── + 📁 ⚙ × ┐
│ [노트] [할 일 3] [완료] [보관함]     │
│ 🔍 검색                           │
│ ── 지남 ─────────────────────── │
│ ● 견적서 회신       10/24 (금)   ⊟ │
│ ── 오늘 ─────────────────────── │
│   월간 보고 ↻       15:00        ⊟ │
│ ── 곧 ───────────────────────── │
│   치과              10/28 (화)    │
│ ── 나중 · 반복 예정 ────────────── │
│   분기 점검 ↻       12/1         │
└──────────────────────────────────┘
```

| 탭 | 보이는 것 | 정렬 |
|---|---|---|
| 노트 | 지금과 같음(완료 노트 제외, 할 일 노트도 포함하되 오른쪽에 작은 마감 칩) | 지금과 같음(📌 고정 먼저) |
| 할 일 (개수 = 지남+오늘) | `due`가 있고 완료 안 된 노트. 지남·오늘·곧·나중 묶음 | 마감 빠른 순, 같은 시각은 이름순 |
| 완료 | `완료` 폴더의 노트. "완료 10/20 · 9일 뒤 삭제" | 완료 최근 순. ↩ 되살리기, 🗑 휴지통 |
| 보관함 | 지금과 같음 | 지금과 같음 |

- **휴지통**은 지금처럼 Windows 휴지통입니다(노트 위젯이 따로 휴지통을 갖지 않음). 완료 탭 아래에 "자동 삭제한 노트는 Windows 휴지통에 있습니다 · 휴지통 열기" 한 줄을 둡니다. 위젯이 직접 휴지통 목록을 만들면 영구 삭제를 위젯이 해야 하므로 만들지 않는 쪽을 추천합니다.
- 할 일 탭의 항목에서 오른쪽 클릭 → 완료 / 날짜 바꾸기 / 노트 열기. 체크 칸은 두지 않습니다(완료는 반복·체크 비우기 같은 동작이 있어 한 번 더 보이는 곳에서만).
- 목록 맨 위 알림 줄(이미 있는 `notice`)에 "자동 삭제: 완료 노트 2개를 휴지통으로 옮겼습니다"를 한 번 보여 줍니다.

### 2.5 창이 열고 닫히는 규칙 정리

| 일 | 창 |
|---|---|
| 날짜 걸기·바꾸기 | 그대로 |
| 알림 시각 | 창이 열려 있으면 그대로 + 카드. 닫혀 있으면 카드만(노트 열기로 엶). **예외**: 반복 노트를 완료해서 닫힌 것이면 다시 연다(설정, 기본 켬) |
| 완료(반복 없음) | 닫힘 → `완료` 폴더 |
| 완료(반복) | 닫힘 → 다음 알림 때 같은 자리에 다시 열림 |
| 되돌리기 / 완료 탭에서 ↩ | 원래 폴더로, 창을 원래 자리에 다시 엶 |
| 다시 알림 | 그대로 |

## 3. 저장 형식

### 3.1 머리말 키

지금 노트 파일은 이미 머리말 한 줄(`desk-widgets-memo: <id>`)을 쓰고, 다른 프로그램의 머리말 줄은 그대로 둡니다. 여기에 **평평한 키 몇 개**를 더합니다. Obsidian 속성 창과 VS Code에서 그대로 읽히고 고칠 수 있게 값은 모두 한 줄 문자열입니다(중첩·목록 없음).

```markdown
---
desk-widgets-memo: 3f9a1c2e-…
due: 2026-11-01 09:00
repeat: 매월 1일
remind: 30분 전
---
# 월간 보고
…
```

| 키 | 값 | 없으면 | 비고 |
|---|---|---|---|
| `desk-widgets-memo` | id (지금과 같음) | 위젯이 처음 저장할 때 붙임 | 그대로 |
| `due` | `YYYY-MM-DD`(종일) 또는 `YYYY-MM-DD HH:mm`(시각) | 그냥 노트 | **할 일인지 정하는 유일한 키**. 반복 노트에서는 "지금 돌아온 회차"의 날짜 |
| `repeat` | 반복 규칙 문구(5.1) | 반복 없음 | `due`가 없으면 무시 |
| `remind` | `마감`, `N분 전`·`N시간 전`·`N일 전 HH:mm`, `없음` | 시각 있음: 마감 시각 / 종일: 설정의 종일 알림 시각 | 날짜창의 🔔 |
| `completed` | `YYYY-MM-DD HH:mm` | 완료 안 됨 | 반복 아닌 노트만. 반복 노트는 쓰지 않음 |
| `last-done` | `YYYY-MM-DD HH:mm` | — | 반복 노트의 마지막 완료(완료 후 반복의 기준). 기록용 |
| `reset-checks` | `true` / `false` | 설정의 기본값(추천: 켬) | 반복 노트 완료 때 체크 목록 비우기 |
| `source` | `dooray` / `mail` | — | 8.2. 같은 원본 중복 방지 |
| `source-id` | 원본 id | — | |
| `source-url` | https 주소 | — | 본문에도 링크로 넣음 |

**`nextDue`를 따로 두지 않는 이유**: 반복 노트도 "지금 해야 하는 날짜"는 하나뿐이라 `due` 하나가 그 값입니다. 완료하면 `due`를 다음 회차로 바꿉니다. 키가 하나면 Obsidian에서 고치는 사람도 헷갈리지 않고, 두 값이 어긋나는 상태가 생기지 않습니다. `done: true` 같은 별도 완료 표시도 같은 이유로 두지 않습니다(`completed`가 있으면 완료).

**키 이름을 `due`처럼 짧게 하는 이유와 위험**: Obsidian Tasks·Dataview 사용자도 `due: YYYY-MM-DD`를 쓰므로 같은 뜻이면 오히려 맞물립니다. 위험은 다른 뜻으로 `due`를 쓰던 노트가 갑자기 할 일이 되는 것인데, 날짜 형식이 아니면 무시(3.3)하고, 날짜면 할 일 탭에 나타나는 것뿐(파일은 안 바꿈)이라 받아들일 만합니다. 접두사(`dw-due`)는 바깥 편집기에서 보기 나빠 추천하지 않습니다 → [12장](#12-사용자가-정할-것) 결정 D.

### 3.2 날짜·시각과 시간대

- 날짜와 시각은 **이 PC의 현지 시각, 시간대 표시 없이**(floating) 적습니다. `due: 2026-11-01 09:00`은 "그 PC에서 11월 1일 오전 9시". 노트는 사람이 읽는 문서이고 Obsidian·Tasks도 같은 방식이라 맞춥니다.
- **종일**(`YYYY-MM-DD`)은 그날 하루 전체입니다. 지남 판정은 다음 날 0시부터. 할 일 위젯처럼 23:59 시각을 만들어 저장하지 않습니다(날짜가 하루 밀리는 문제 없음).
- 시간대를 옮긴 PC(해외 출장)에서도 같은 벽시계 시각으로 알립니다. 서머타임이 있는 시간대에서 없는 시각(봄 2:30)은 그 뒤 첫 시각으로, 두 번 있는 시각은 첫 번째로 봅니다.
- 위젯 안(메모리·연동)에서는 할 일 위젯과 같은 `dueAt`(ms) + `dateOnly`로 바꿔 씁니다. 캘린더 연동 형식이 그대로 맞습니다(8.1).

### 3.3 바깥 편집과 잘못된 머리말

- **머리말이 없거나 깨진 파일 = 그냥 노트.** 할 일 키만 못 읽을 뿐 노트는 지금처럼 열리고 고쳐집니다.
- 키 하나가 잘못되면(`due: 내일쯤`, `repeat: 가끔`) **그 키만 무시**하고 파일은 **고치지 않습니다**. 노트 창 마감 줄에 "⚠ 날짜를 읽을 수 없음: 내일쯤 · 다시 정하기"를 보여 주고, 사용자가 다시 정할 때만 그 줄을 바꿉니다.
- 위젯이 머리말을 쓸 때는 **자기 키의 줄만** 바꾸거나 넣고, 다른 줄(Obsidian `tags`, `aliases` 등)·순서·주석은 그대로 둡니다(지금 id 줄을 다루는 방식과 같음). 값은 따옴표 없이 쓰되 읽을 때는 `"…"`·`'…'`도 받습니다.
- 같은 키가 두 번 있으면 첫 번째를 씁니다. 키 이름은 대소문자를 구분하지 않고 읽습니다(`Due:`도 됨), 쓸 때는 소문자.
- 날짜 형식은 `2026-11-01`, `2026-11-01 09:00`, `2026-11-01T09:00`(VS Code·다른 도구가 쓰는 꼴)을 모두 읽습니다. 쓸 때는 띄어쓰기 꼴.
- 바깥에서 `due`·`repeat`·`completed`를 바꾸면 폴더 감시가 지금처럼 다시 읽어 창·목록·알림 예정·캘린더를 맞춥니다. 저장하지 않은 내용이 있을 때의 충돌 처리(바뀐 내용 보기 / 내 내용으로 저장 / 사본)는 머리말 변경에도 똑같이 적용됩니다.
- 바깥에서 `completed`를 지우면 미완료로 보고, 파일이 `완료` 폴더에 있으면 원래 폴더로 옮기지는 않고 목록에서 "완료 폴더에 있지만 완료 안 됨"으로 표시해 ↩ 하나로 꺼내게 합니다(위젯이 바깥 편집을 따라 파일을 옮기지 않음).

### 3.4 파일에 넣지 않는 것

알림 상태(`remindedFor`), 다시 알림(`snoozedUntil`), 창 위치·색·열림은 **위젯 설정 파일**(`settings.json`의 `memos[id]`)에 둡니다. 알림 한 번에 파일을 고치면 OneDrive 충돌 사본과 Obsidian의 "바깥에서 바뀜"이 잦아지기 때문입니다. 파일은 사용자가 뜻을 바꿀 때(날짜·반복·완료)만 바뀝니다. 다른 PC에서 같은 폴더를 쓰면 다시 알림 상태는 PC마다 따로입니다.

### 3.5 지금 노트에서 옮겨 오기

- **따로 옮길 것이 없습니다.** 머리말에 `due`가 없는 지금의 모든 노트는 그대로 노트입니다. 파일을 열기만 해서 고치지도 않습니다.
- 할 일 기능이 없는 이전 버전(1.1.x)으로 되돌려 설치해도, 이전 버전은 모르는 머리말 줄을 그대로 두므로 파일이 깨지지 않습니다. 단 `완료` 폴더의 노트는 이전 버전 목록에 보이지 않습니다(하위 폴더를 보지 않음, 파일은 그대로).

## 4. 날짜 문구 해석기

할 일 위젯의 `lib/dates.js`(문장 **끝**의 날짜 문구만 읽어 제목을 해치지 않는 방식)를 출발점으로 하되, 지금은 `오늘·내일·모레·다음 주 X요일·매주 X요일 + 시각`만 읽습니다. 사용자가 원하는 `10/30`, `매월 1일` 등을 위해 넓힙니다. 위젯끼리 코드를 공유하지 않는 규칙(#40, 위젯 패키지에 node_modules 없음)에 따라 **노트 위젯에 복사해 넓히고**(`widgets/memo/lib/dates.js`), 할 일 위젯은 동결이므로 건드리지 않습니다.

| 종류 | 받는 문구 (예) |
|---|---|
| 상대 날짜 | 오늘, 내일, 모레, 글피, 3일 뒤, 2주 뒤, 다음 달 |
| 요일 | 금요일, 금, 이번 주 금, 다음 주 월요일, 주말(토) |
| 날짜 | 10/30, 10.30, 10월 30일, 30일(이번 달, 지났으면 다음 달), 2026-10-30, 2027년 1월 5일 |
| 시각 | 오후 3시, 3시 반, 15:30, 아침(9시), 점심(12시), 저녁(18시), 밤(21시). 시각만 쓰면 오늘, 지났으면 내일(지금과 같음) |
| 정해진 반복 | 매일, 평일, 주말, 매주 금, 매주 월수금, 격주 화, 매월 1일, 매월 말일, 매월 첫째 월요일, 매월 마지막 금요일, 매년 3월 15일, 3일마다, 2주마다, 3개월마다 |
| 완료 후 반복 | 완료 후 30일, 완료 후 2주, 완료 후 3개월 |
| 영어(UI가 영어일 때) | today, tomorrow, mon, next mon, 10/30, 3pm, every day, every fri, every month on 1, every 2 weeks, after 30 days |

- `10/30`은 월/일(한국식)로 읽습니다. 이미 지난 날짜면 내년.
- 날짜창·`/` 명령은 문구 **전체**를 날짜로 읽고, 첫 줄 제안(2.2③)만 "끝부분" 방식으로 읽습니다.
- 해석 결과를 다시 사람이 읽는 문구로 바꾸는 `format()`을 함께 두어 머리말 `repeat` 값과 칩 글자를 만듭니다. **`repeat`에는 이 정규화한 문구를 씁니다**(예: 사용자가 "매달 1일"이라 쳐도 `매월 1일`로 저장). 읽을 때는 해석기가 받는 모든 문구를 받으므로 Obsidian에서 고쳐 써도 됩니다.
- 테스트: 지금 `widgets/todo/test`의 날짜 테스트를 옮기고, 위 표의 모든 예 + 경계(월말, 윤년 2/29, 연말, 자정 직전, 오전 12시/오후 12시)를 고정 시각으로 검사.

## 5. 반복

### 5.1 두 종류

| 종류 | 규칙 예 | 다음 회차 계산 |
|---|---|---|
| **정해진 날** | 매월 1일, 매주 금, 평일, 2주마다 | 규칙의 회차 중 **지금 `due`보다 뒤이면서 오늘보다 뒤**인 첫 회차 |
| **완료 후** | 완료 후 30일 | 완료한 **날짜** + 기간(시각은 원래 `due`의 시각 유지, 종일이면 종일) |

`N일마다`·`N주마다`·`N개월마다`(정해진 날 쪽)는 처음 건 `due`를 기준점으로 셉니다. 기준점은 따로 저장하지 않고 "지금 `due`에서 N만큼씩"으로 계산하므로, 사용자가 `due`를 옮기면 그 날짜가 새 기준점이 됩니다.

월 반복의 없는 날짜: `매월 31일`은 30일까지인 달에 **그달 마지막 날**로(다음 회차는 다시 31일 기준). Todoist·Google 캘린더와 같습니다.

### 5.2 반복 노트에서 "완료"

1. `due`를 다음 회차로 바꾸고 `last-done`에 지금 시각을 씁니다. `completed`는 쓰지 않으며, 파일은 `완료` 폴더로 가지 않고 **제자리**에 남습니다.
2. 체크 목록 비우기: `reset-checks`가 켜져 있으면 본문의 `- [x]`를 모두 `- [ ]`로 바꿉니다(코드 블록 안은 그대로). 바뀐 수를 완료 알림에 "체크 5개를 비웠습니다 · 되돌리기"로 보여 줍니다.
3. 창을 닫고, 다음 알림 때 다시 엽니다(2.5).

**체크 비우기 기본값 추천: 켬.** 사용자가 말한 쓰임새(매달 같은 절차를 체크하며 하는 보고서 가이드)에서는 비워져야 다음 달에 바로 쓸 수 있습니다. 끈 노트는 체크가 그대로 남아 "지난번 어디까지 했나" 기록으로 쓸 수 있습니다. 노트마다 날짜창의 반복 칸 아래 "완료하면 체크 비우기 ☑"로 바꿉니다(`reset-checks` 줄). 비우기 전 내용은 되돌리기를 위해 메모리에 8초 동안만 들고 있습니다(따로 기록 파일을 만들지 않음) → 결정 E.

### 5.3 놓친 회차

- 정해진 날 반복에서 `due`가 지나도 **새 회차를 자동으로 만들거나 `due`를 저절로 넘기지 않습니다.** 노트는 "지남" 상태로 남고 알림 카드는 처음 한 번 + 다시 알림만(회차마다 쌓이지 않음).
- 늦게 완료하면 지난 회차들은 건너뛰고 **오늘 뒤의 첫 회차**로 갑니다. 예: 매월 1일 보고를 11/3에 완료 → 다음은 12/1(11/1 회차를 다시 만들지 않음). 사흘씩 밀린 회차가 줄줄이 생기지 않는 Todoist의 기본 동작과 같습니다.
- 지난 회차가 2번 이상이면 칩에 `지남 · 2회`를 표시해 놓쳤음을 알립니다.
- 위젯이 꺼져 있던 동안에도 계산은 `due` 하나로 하므로 켜는 순간 맞는 상태가 됩니다.

### 5.4 규칙 바꾸기

- 날짜창에서 반복을 바꾸면 **`due`는 그대로** 두고 규칙만 바꿉니다. 단 새 규칙에 지금 `due`가 맞지 않으면(매월 1일 → 매월 15일인데 `due`가 11/1) "다음 날짜를 11/15로 맞출까요? [맞추기] [그대로]"를 묻습니다. 기본 버튼은 맞추기.
- 반복을 **없음**으로 바꾸면 보통 할 일 노트가 됩니다(`last-done`은 남겨 둠).
- 날짜를 지우면(노트로 되돌리기) `due`·`repeat`·`remind`·`reset-checks`를 지웁니다. `last-done`·`source…`는 남깁니다.
- 바깥 편집기에서 `repeat`만 바꾼 경우는 묻지 않고 그대로 따릅니다(다음 완료 때 새 규칙으로 계산).

## 6. 완료와 자동 삭제

### 6.1 완료 폴더

- 반복이 아닌 노트를 완료하면 `completed: <지금>`을 쓰고 파일(과 `.assets` 폴더)을 노트 폴더의 **`완료` 하위 폴더**로 옮깁니다. 지금의 `보관함`과 같은 방식이라 Obsidian·탐색기에서 노트 폴더가 완료 노트로 어지러워지지 않고, 지금 코드(이름 겹침 처리·assets 함께 옮기기)를 그대로 씁니다.
- `[[이름]]` 링크는 `완료` 폴더의 노트도 찾습니다(보관함과 같은 규칙: 열면 "완료된 노트입니다 · 되살리기").
- 완료 탭의 ↩ 되살리기: `completed` 줄을 지우고 원래 폴더로.

### 6.2 자동 삭제

| 설정 "완료한 노트 자동 삭제" | 값 |
|---|---|
| 선택지 | 7일 / 14일 / **30일(기본)** / 90일 / 1년 / 삭제 안 함 |

- 대상: `완료` 폴더에 있고, 머리말에 **위젯 id**와 올바른 `completed`가 있고, `repeat`이 **없는** `.md` 파일. 이 조건을 하나라도 벗어나면 손대지 않습니다(사용자가 손으로 넣은 파일, 깨진 머리말 포함).
- 기준 시각: `completed`와 파일 수정 시각 중 **늦은 것**. 완료한 뒤 Obsidian 등에서 고친 노트는 고친 날부터 다시 셉니다(사용자가 아직 쓰는 노트를 지우지 않게). 그래서 "바깥에서 고친 파일에도 적용되나?"의 답은 "적용되지만 고친 날부터 다시 센다"입니다.
- 지우는 방법: **Windows 휴지통으로 옮기기**(`shell.trashItem`, 지금 노트 삭제와 같음). 영구 삭제는 위젯이 하지 않습니다. 휴지통으로 못 옮기면(네트워크 드라이브 등) 지우지 않고 목록에 "자동 삭제를 못 했습니다(휴지통 없음)"을 한 번 알립니다.
- 시점: 위젯을 켤 때와 6시간마다. 한 번에 최대 50개(많으면 다음 번에 이어서).
- 노트 창이 열려 있는 노트는 건너뜁니다(완료 노트를 사용자가 다시 열어 둔 경우).
- 기간을 줄이면 다음 확인 때 새 기간으로 적용됩니다. 설정 화면에 "지금 기준 N개가 휴지통으로 갑니다"를 미리 보여 줍니다.
- 반복 노트는 완료해도 `완료` 폴더로 가지 않으므로 자연히 지워지지 않습니다(사용자 결정 3).

### 6.3 기존 휴지통·보관함과의 관계

| 기능 | 폴더 | 자동 삭제 |
|---|---|---|
| 보관함 | `보관함` | 없음(지금과 같음) |
| 완료 | `완료` | 설정 기간 뒤 Windows 휴지통 |
| 휴지통으로 옮기기 | Windows 휴지통 | Windows가 관리 |

완료 노트를 보관함으로 옮기면 `completed`는 남지만 자동 삭제 대상이 아닙니다(보관함은 "지우지 말고 치워 두기"라는 뜻이므로).

## 7. 알림·일정 엔진 (위젯 안)

- 할 일 위젯의 방식(메인 코드가 다음 알림까지 `setTimeout`, 최대 30초 간격으로 다시 확인, 보내기 전에 `remindedFor`를 저장해 중복 카드 방지)을 그대로 옮깁니다.
- 알림 계산은 **폴더 전체 색인**(지금 `library`의 목록 캐시)에서 합니다. 노트 창이 닫혀 있어도 알림이 옵니다. 색인에 머리말 할 일 키를 더해 파일을 매번 다시 읽지 않습니다.
- 노트 수가 많아도 가볍게: 알림 계산은 할 일 노트만, 정렬된 다음 시각 하나만 타이머로.
- 자리 비움(`setPaused`)·절전에서 돌아오면 바로 한 번 확인합니다.

## 8. 연동

### 8.1 캘린더 마감 표시

지금(#94)은 엔진의 허용 표에 `calendar → todo: tasks.snapshot, tasks.updateDue`와 `todo → calendar: tasks.changed`가 **위젯 id로 박혀 있습니다**(`engine/main/widgets.js` `INTEGRATION_CALLS`). 노트 위젯(id `memo`)이 같은 일을 하려면 엔진이 바뀌어야 합니다.

| 바뀌는 것 | 내용 |
|---|---|
| 엔진 허용 표 | `calendar → memo: notes.snapshot, notes.updateDue`, `memo → calendar: notes.changed` 추가. **`todo` 줄은 지우지 않음**(동결 위젯도 계속 동작) |
| 노트 위젯 | `notes.snapshot` → `{ tasks: [{ id, title, dueAt, dateOnly, completedAt, repeat, source }] }`. 할 일 위젯의 `tasks.snapshot`과 **같은 모양**이라 캘린더 코드 재사용. `notes.updateDue` → 그 노트 머리말의 `due`만 바꿈(창이 열려 있으면 그 세션을 거쳐 저장해 충돌 없음). 설정 "캘린더에 마감 표시" |
| 캘린더 위젯 | 할 일 출처를 **둘 다** 받음: "스티키 노트" 오버레이(새, 기본)와 "할 일 목록(이전)" 오버레이(이미 켠 사람만 보임). 각각 켜고 끔, 색도 따로. 표시 id는 `memo:<노트 id>` / `todo:<id>` |
| 캘린더에서 누르면 | 노트 출처는 상세 창에 **노트 열기** 버튼(새, 메서드 `notes.open` 하나 더 허용). 날짜 편집은 지금 할 일 편집창 그대로 |

- 반복 노트는 **지금 회차(`due`) 하나만** 표시합니다. 앞으로의 회차를 미리 그리는 것은 나중(캘린더에 "반복 예정 보기" 옵션)으로 미룹니다. 표시 id가 노트 id 하나라 완료하면 칩이 다음 회차로 "옮겨 가는" 모양이 됩니다.
- 완료 노트(`완료` 폴더)는 캘린더의 "완료 숨김/완료 표시" 설정을 그대로 따릅니다. 자동 삭제되면 사라집니다.
- 바깥 편집으로 `due`가 바뀌어도 폴더 감시 → `notes.changed` → 캘린더가 전체 스냅샷을 다시 읽는 지금 방식 그대로입니다.

### 8.2 두레이·메일 "할 일로 추가" → 노트

지금 두레이·메일은 `ctx.integrations.call('todo', 'tasks.addExternal', …)`를 부릅니다. 바뀌는 것:

- 엔진 허용 표: `dooray → memo: notes.addExternal`, `mail → memo: notes.addExternal`, 그리고 `notes.open`(이미 있는 노트 열기).
- 두레이·메일 위젯: 보낼 곳을 고르는 로직(아래 8.3)과 본문을 함께 보냄.
- 노트 위젯: `notes.addExternal(input)` → 노트 파일을 만들고 **그 노트 창을 열어** 줍니다.

만들어지는 노트:

```markdown
---
desk-widgets-memo: 7c1e…
due: 2026-10-30
source: dooray
source-id: 3912345678901234567
source-url: https://example.dooray.com/project/posts/3912345678901234567
---
# [기획] 견적서 회신

[두레이에서 열기](https://example.dooray.com/project/posts/3912345678901234567) · 프로젝트 영업지원 · 담당 홍길동 · 마감 10/30

---

(업무 본문)
```

| 항목 | 두레이 | 메일 |
|---|---|---|
| 노트 이름(첫 줄) | 업무 제목 | 메일 제목(`RE:`·`FW:` 빼지 않음) |
| `due` | 업무 마감일(있으면). 사용자가 추가 창에서 바꿀 수 있음(지금 #94 UI) | 사용자가 추가 창에서 고른 날짜(없으면 그냥 노트) |
| 첫 줄 아래 정보 | 원본 링크, 프로젝트, 담당자, 마감 | 원본 열기 링크(웹메일 주소가 있을 때만), 보낸 사람, 받은 시각 |
| 본문 | 업무 본문(두레이는 Markdown이라 그대로, 위젯 정리기를 거침). 20,000자까지, 넘으면 자르고 "…(원본에서 계속)" | 메일 본문을 **글자로** 바꾼 것(HTML은 메일 위젯의 정리기에서 텍스트로, 인용 부분 `>`), 20,000자까지. **첨부 파일은 복사하지 않고** 이름만 목록으로 |
| 댓글 | 넣지 않음 | — |

- **사용자 결정 2에 따라 본문을 넣습니다.** #94의 "본문·첨부 자동 복사하지 않음"을 이 범위만큼 바꾸는 것이므로 정책 행과 [할 일 연동 기획](todo-calendar-integration.md)에 "#110부터 노트에는 본문을 넣음"을 적습니다. 본문을 넣는 것은 사용자가 누른 그 한 번뿐이고, 원본이 나중에 바뀌어도 노트를 고치지 않습니다(지금과 같음).
- **중복**: 같은 `source`+`source-id`인 노트가 있으면(완료·보관함 포함) 새로 만들지 않고 그 노트를 엽니다("이미 노트가 있습니다"). 사용자가 노트에서 `source-id` 줄을 지우면 별개 노트가 됩니다.
- 위젯 정리기(허용 목록)를 거치므로 원본 HTML·스크립트가 노트 창에서 실행되지 않습니다. 이미지는 넣지 않습니다(원본 이미지는 인증이 필요한 주소라 어차피 보이지 않음).
- 엔진 연동 전달 크기 제한 2 MB 안에 들어갑니다(20,000자 ≈ 60 KB).

### 8.3 할 일 목록 위젯을 가진 사용자

연동의 "할 일 쪽" 위젯이 둘이 될 수 있으므로 두레이·메일·캘린더에 **보낼 곳**이 필요합니다.

| 상황 | 두레이·메일 "할 일로 추가" | 캘린더 |
|---|---|---|
| 노트(새 버전)만 | 노트 | 노트 오버레이 |
| 할 일 목록만(노트 없음 또는 이전 노트) | 할 일 목록(지금 그대로) | 할 일 오버레이 |
| **둘 다** | 설정 "추가할 곳: **스티키 노트**(기본) / 할 일 목록(이전)" | 두 오버레이 모두 가능, 노트만 기본 켬 |

- 두레이·메일의 설정 이름은 지금 "할 일 연동"을 그대로 쓰고, 그 아래에 "추가할 곳" 줄을 **둘 다 있을 때만** 보입니다. 필요 조건 표시(#94)는 고른 곳 기준으로 보여 줍니다.
- 노트 쪽 받기 설정은 노트 위젯 설정의 "두레이에서 받기"·"메일에서 받기"·"캘린더에 마감 표시"(지금 할 일 위젯 설정과 같은 세 줄, 기본 끔 — #94 원칙).
- 고르기를 엔진이 아니라 각 위젯이 하는 이유: 엔진 허용 표는 "누가 누구를 부를 수 있나"만 정하고, 무엇을 고를지는 사용자 설정이라 위젯에 있어야 합니다.
- **역량 이름**: 노트 위젯은 `notes-receive-external`, `notes-calendar-share`를 선언합니다. 두레이·메일·캘린더는 상대의 역량으로 기능 지원을 확인합니다(지금 `todo-receive-external`과 같은 방식).

### 9.4 할 일 → 노트 가져오기

**추천: 한다(선택 기능, 마지막 단계).** 할 일 목록은 공개된 지 며칠이라 쓰는 사람이 적지만 사용자 본인이 쓰고 있고, 손으로 옮기면 날짜·반복을 다시 쳐야 합니다.

문제는 **동결된 할 일 위젯은 새 메서드를 열 수 없다**는 것입니다(지금 열린 `tasks.snapshot`은 캘린더에만, 날짜 있는 항목만 줌). 방법:

| 방법 | 장단점 |
|---|---|
| **A. 엔진이 읽어 건네기 (추천)** | 엔진에 `ctx.integrations.importLegacy('todo')` 하나: 사용자가 노트 설정에서 **가져오기**를 누른 직후에만, 엔진이 `widgets/todo/settings.json`을 읽기 전용으로 읽어 할 일 위젯의 정리 규칙과 같은 모양(목록·할 일)으로 노트 위젯에 건넴. 위젯끼리 파일을 직접 읽지 않는 원칙(#94)을 지키고 할 일 위젯은 손대지 않음. 엔진 코드 50줄 정도 |
| B. 노트 위젯이 파일을 직접 읽기 | 가장 쉽지만 위젯 경계 원칙 위반 |
| C. 할 일 위젯 마지막 버전(1.1.1)에 내보내기 추가 | 사용자 결정 1(새 버전 없음)과 어긋남 |
| D. 하지 않음 | 일이 없음. 사용자가 손으로 옮김 |

가져오는 방식(A일 때):

- **날짜나 반복이 있는 할 일** → 할 일마다 노트 하나(이름 = 제목, `due`, `repeat: 매주 금`(할 일 위젯의 `repeatWeekday`), 출처가 있으면 `source…`).
- **날짜 없는 할 일** → 목록마다 노트 하나(`할 일 - <목록 이름>`), 본문은 `- [ ] 제목` 체크 목록. 노트로 쓰기에는 이쪽이 자연스럽습니다.
- 완료한 할 일은 기본으로 가져오지 않음(☐ "완료한 것도 가져오기"를 켜면 `완료` 폴더로, 완료 시각 그대로라 자동 삭제 기간이 그때부터 셈).
- 가져온 뒤 할 일 위젯 데이터는 지우지 않습니다. 같은 할 일을 두 번 가져오지 않도록 노트 머리말에 `source: todo`, `source-id: <할 일 id>`.
- 결과: "노트 7개, 체크 목록 노트 2개를 만들었습니다 · 할 일 목록 위젯은 위젯 관리에서 끌 수 있습니다".

| C. 전부 | 노트·할 일 | productName `NoteTodoWidget`, 문서 폴더 `노트` | 설치 파일 이름 바뀜, 제어판 항목 이름 바뀜(id가 같아 #95처럼 덮어씀), 문서 폴더를 한 번 더 옮겨야 함(#95의 옮기기 코드 재사용, OneDrive 위험), 검색 노출 다시 |

**A를 추천하는 이유**: #95에서 막 "메모 → 스티키 노트"로 바꾸고 폴더까지 옮겼고, 다운로드 페이지 검색 문구(#106)도 "스티키 노트"로 잡았습니다. 날짜를 걸지 않으면 노트 그대로라는 개념에도 "스티키 노트"가 맞습니다. 대신 설명을 바꿉니다:

> **스티키 노트** — 노트마다 창 하나, Markdown 파일로 저장하는 스티키 노트. 날짜를 걸면 할 일이 되어 알림·반복·캘린더 마감까지.

내부 이름 "todonote"는 이슈·문서 이름으로만 씁니다. 바꾼다면 B까지만(폴더·productName은 그대로) 추천합니다 → 결정 A.

## 11. 엔진·API, 시험, 단계

### 11.1 엔진·API 영향

| 변경 | 왜 | API |
|---|---|---|
| 허용 표에 `memo` 줄(`notes.addExternal`, `notes.snapshot`, `notes.updateDue`, `notes.open`, 이벤트 `notes.changed`) | 8.1·8.2 | **1.7** (ctx 모양은 같지만 이전 엔진에서는 `route-denied`라, 위젯이 "엔진 업데이트 필요"를 구분하려면 API 값으로 알아야 함) |
| `importLegacy('todo')` (9.4 A) | 가져오기 | 1.7에 같이 |
| `products.json`의 `frozen` 읽어 관리 창에 안내 (9.3) | 선택 | 엔진만, API 무관 |

- 노트 위젯 `engineApi`: 지금 1.0 → **1.2**(일반 알림 카드·`onAction`이 필수). 카드 메뉴(1.4)·연동(1.7)·공유 창(#109)은 있으면 쓰는 방식(기능 확인)으로 두어, 1.2~1.6 엔진에서도 노트·할 일·알림은 되고 메뉴·연동만 빠지게 합니다. → 노트 위젯 `engineMin`이 1.0.0에서 1.0.1(API 1.2 엔진)로 올라감.
- 엔진은 바뀐 만큼 다음 엔진 버전이 됩니다(버전은 제품별).

### 11.2 시험 계획

| 범위 | 내용 |
|---|---|
| 해석기 단위 | 4장의 모든 문구, 경계(월말·윤년·연말·자정·오전/오후 12시), `format()` 되돌리기(해석 → 문구 → 해석 같음), 영어 |
| 머리말 | 읽기/쓰기: 다른 줄·순서 보존, 따옴표, `T` 꼴, 대소문자, 중복 키, 잘못된 값(파일 안 바뀜), 머리말 없음·닫는 `---` 없음, BOM, CRLF |
| 반복 | 정해진 날·완료 후, 놓친 회차 건너뛰기, `매월 31일`, 규칙 바꾸기(맞추기/그대로), 체크 비우기(코드 블록 제외)·되돌리기 |
| 완료·자동 삭제 | `완료` 폴더 이동(assets 함께, 이름 겹침), 되살리기, 기간별 삭제(가짜 시계), 수정 시각 기준, 위젯 id 없는 파일·반복 노트·열린 노트 건너뛰기, 휴지통 실패 시 지우지 않음 |
| 알림 | 가짜 시계로 시각 알림·종일 9시·다시 알림·중복 없음·꺼진 동안 12시간·요약 카드, 카드 버튼 3개 동작 |
| 바깥 편집 | VS Code처럼 머리말만 바꿈 → 창·목록·캘린더 갱신, 저장 안 한 내용과 충돌, OneDrive 충돌 사본에 `due`가 있을 때 할 일이 둘로 보이지 않음(사본은 할 일 목록에서 빼고 "충돌 사본"만) |
| 연동 | 엔진 허용 표(새 줄 허용·옛 줄 유지·없는 줄 거부), 두레이·메일 → 노트 생성·중복·본문 자르기·정리기, 보낼 곳 고르기(노트만/할 일만/둘 다), 캘린더 두 오버레이·날짜 편집·노트 열기, 이전 엔진에서 "엔진 업데이트 필요" |
| 동결 | `release:all`·CI가 todo를 건너뜀, `products.json`에 1.1.0 + `frozen`, 할 일 위젯 테스트가 새 엔진에서 통과 |
| 가져오기 | 날짜 있음/없음/반복/출처/완료 포함, 두 번 가져오기 중복 없음, 할 일 데이터 그대로 |
| 실제 확인 (사용자 PC, 내부 테스트 빌드) | 날짜창·`/` 명령·첫 줄 제안 손으로, 실제 알림 카드, Win+D 뒤 다시 열린 반복 노트 창, Obsidian에서 속성 편집, 실제 두레이·메일 추가 |

### 11.3 단계와 크기

| 단계 | 내용 | 크기(대략) |
|---|---|---|
| 1 | 해석기 넓히기 + 머리말 읽기/쓰기 + 색인에 할 일 키 | 2~3일 |
| 2 | 노트 창: ⏰·날짜창·마감 줄·완료·`/` 명령·첫 줄 제안 | 3~4일 |
| 3 | 알림 카드·다시 알림·반복·체크 비우기·창 다시 열기 | 2~3일 |
| 4 | 목록 4탭·`완료` 폴더·자동 삭제·설정 | 2~3일 |
| 5 | 엔진 1.7 허용 표 + 노트 연동 메서드 + 캘린더 두 오버레이 + 두레이·메일 보낼 곳·본문 | 3~4일 |
| 6 | 할 일 동결: 버전 되돌리기·`frozen`·릴리스 도구·사이트 문구·showcase | 1일 |
| 7 | (선택) 할 일 가져오기 + 관리 창 안내 | 1~2일 |
