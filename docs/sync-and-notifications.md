# 갱신과 알림 동작 방식

두레이 API를 언제, 몇 번 부르는지와 알림을 무엇으로 판단하는지 정리합니다.

## 갱신 주기

설정의 **새로고침 주기**(기본 45초)마다 한 번씩 확인합니다. 화면 잠금·절전·자리 비움 중에는 **확인하지 않고**, 돌아오면 바로 확인합니다.

### 한 번의 확인에서 하는 일

1. **변경 확인 (1요청)**
   `GET /project/v1/posts?projectIds=<표시 프로젝트들>&updatedAt=<마지막으로 본 시각>~`
   - 마지막으로 본 시각은 PC 시계가 아니라 **두레이 서버의 updatedAt**(+1초)을 기준으로 합니다.
2. 바뀐 게 없으면 끝. 가지고 있는 데이터로 다시 집계만 합니다. (지연·임박 판정은 현재 시각 기준으로 계속 갱신)
3. 바뀐 게 있으면 **전체 다시 읽기**:
   - 미완료 업무 전체: 모든 표시 프로젝트를 한 번에 (`/project/v1/posts?projectIds=...`, 100건당 1요청)
   - 최근 7일 완료 업무 (완료 건수 계산용)
   - 분류에 넣었지만 목록에 없는 업무(완료·숨긴 프로젝트) 단건 조회
   - 알림 판단, 필요하면 댓글 조회 (아래 참고)

### 요청 수 (프로젝트 15개 기준, 실측)

| 상황 | 요청 |
|---|---|
| 변화 없음 | **1건** (약 0.1초) |
| 변화 있음 | 3건 + 댓글 조회(알림 설정에 따라) |
| 앱 시작 | 4건 + 태그 목록(프로젝트 수만큼) |
| 새로고침 버튼 | 전체 다시 읽기 (아래 표) |
| 잠금·자리 비움 중 | 0건 |

이전 방식(프로젝트마다 요청)은 변화가 없어도 약 17건/5초였습니다.

### 주기적으로만 다시 받는 것

| 항목 | 다시 받는 때 |
|---|---|
| 프로젝트 목록 | 10분마다, 새로고침 버튼 |
| 전체 다시 읽기 | 변경 감지 시, 10분마다(삭제 등 변경 감지로 못 잡는 경우 대비), 새로고침 버튼, 표시 프로젝트 변경 |
| 태그 목록(이름·색) | 30분마다, 새로고침 버튼, 표시 프로젝트 변경 |
| 내 계정 정보 | 앱 시작 시 1회 |

### 새로고침 버튼 (↻)

변경 확인을 건너뛰고 **프로젝트 목록, 미완료 업무, 최근 완료, 분류에 넣은 업무, 태그 목록**을 모두 새로 받습니다. 받은 데이터를 직전 데이터와 비교해 바뀐 점이 있으면 알림도 뜹니다. 이미 본 알림이 다시 뜨지는 않습니다.

### 요청 제한(429) 대응

- 모든 요청은 공용 대기열을 거칩니다: 동시에 2개, 요청 사이 120ms
- 429 응답이면 `Retry-After` 또는 1·2·4초 대기 후 최대 3회 재시도
- 갱신이 연속으로 실패하면 주기를 늘려 재시도(최대 10분)

## 알림 판단

두레이 API가 알림을 주지 않으므로, 위젯이 **직전에 받은 업무 목록과 새 목록을 비교**해서 판단합니다. "나"는 `members/me`의 멤버 ID입니다.

| 알림 | 판단 기준 |
|---|---|
| 새 업무 | 처음 보는 업무 ID이고, `createdAt`이 마지막으로 본 시각 이후이며, 등록자(`users.from`)가 내가 아님 |
| 나에게 배정 | 담당자(`users.to`)에 이전엔 내가 없었는데 지금은 있음 |
| 상태 변경 | 내 업무 범위 안 업무의 `workflow`(ID·분류)가 바뀜. 카드에 `접수 → 할당`처럼 표시 |
| 완료 | 이전엔 미완료였던 범위 안 업무가 최근 완료 목록에 나타남 |
| 마감 지남 | 범위 안 업무의 마감 상태가 직전 주기에는 '지남'이 아니었는데 지금은 '지남' (요청 없이 시계로 판단) |
| 새 댓글 | 바뀐 업무의 댓글 목록에서 마지막으로 본 시각 이후, 다른 사람이 쓴 댓글 |
| 댓글 수정 (선택, 기본 꺼짐) | 바뀐 업무의 댓글 중 앞서 본 댓글의 본문이 달라짐(API에 수정 시각이 없어 본문 지문을 비교, 앱이 켜진 동안 본 댓글만). 내 수정은 제외, 새 댓글이 있으면 새 댓글로, 수정으로 내 멘션이 생기면 멘션. 켜져 있어야만 지문을 기억하고, 요청은 늘지 않음 |
| 나를 멘션 | 새 댓글 또는 새 업무 본문에 `[@이름](dooray://…/members/<내 ID>)`가 있음 |

**내 업무 범위**: 설정의 담당 / 참조(`users.cc`) / 내가 작성(`users.from`) 중 켠 것. 멘션은 범위와 관계없이 알립니다.

### 정리 규칙

- 앱을 켠 직후 첫 조회는 **기준점**으로만 씁니다 (기존 업무로 알림이 쏟아지지 않도록).
- 한 업무에 변화가 여러 개면 가장 중요한 1건만: 멘션 > 배정 > 새 댓글 > 댓글 수정 > 새 업무 > 완료 > 상태 변경 > 마감 지남
- 한 번에 10건을 넘으면 요약 카드 1장으로 묶습니다.

### 댓글·멘션 알림의 추가 요청

댓글은 업무 목록 API에 없어서 따로 읽어야 합니다. 댓글이 달리면 업무의 `updatedAt`이 바뀌므로 변경 확인(1요청)이 이미 잡아내고, 그 업무만 댓글을 읽습니다.

| 설정 | 변화가 있을 때 추가 요청 |
|---|---|
| 댓글·멘션 알림 끔 | 없음 |
| 새 댓글만 켬 | 범위 안의 바뀐 업무 수만큼 |
| 멘션 켬 | 바뀐 업무 수만큼 (+ 새 업무 본문) |

- 주기당 최대 20건
- 댓글 작성자 이름은 업무 데이터에 있는 이름을 재사용하고, 없을 때만 1회 조회 후 기억

### 알림이 뜨지 않는 경우 (현재 한계)

- **앱이 꺼져 있던 동안**의 변경: 비교 기준을 메모리에만 두기 때문
- **숨긴 프로젝트**의 업무 변경
- 이미 오래전에 완료된 업무에 달린 댓글
- **내가 직접 바꾼 상태 변경·완료**는 알림이 뜹니다: 두레이 API가 누가 바꿨는지 알려 주지 않음 (내가 등록한 새 업무, 내가 쓴 댓글은 구별해서 알리지 않음)

## 조건 알림 확인

- 매 갱신 주기마다 "확인할 규칙이 있나"만 계산합니다(요청 없음). 규칙의 확인 시각이 지났고 오늘 아직 확인하지 않았으면 그때 확인합니다.
- 확인 1회 = 규칙의 프로젝트들을 한 번에 조회 1건: `GET /project/v1/posts?projectIds=...&createdAt=<시작>~<끝>` (완료 업무 포함)
- 태그 조건이 있고 위젯에 표시하지 않는 프로젝트라 태그 이름을 아직 모르면, 그 프로젝트의 태그 목록을 1회 더 받습니다.
- 잠금·자리 비움 중에는 갱신이 멈추므로 확인도 미뤄지고, 돌아오면 바로 확인합니다.
- "다시 알림"이 켜져 있으면 해결될 때까지 지정 간격마다 다시 확인합니다(그때마다 1요청).
- 조건 알림은 요약 카드로 묶이지 않고 항상 자기 카드로 뜹니다. 설정의 '업무 변경 알림 사용'을 끄면 함께 꺼집니다.

## 알림 카드 표시

- 화면 오른쪽 아래에 겹치지 않게 쌓임 (화면 높이를 넘지 않게 최대 개수 자동 제한). **가장 새 카드가 맨 위**, 오래된 카드가 아래 (#42)
- 새 카드는 항상 바로 맨 위에 표시. 최대 개수 미만이면 기존 카드는 움직이지 않음
- 최대 개수를 넘으면 **가장 오래된 표시 카드가 빠져 대기**(카드 내용만 보관하고 창은 닫음 → 다시 보일 때 새 창)하고 나머지는 한 칸씩 내려감. 여러 개가 한꺼번에 오면 새것들이 자리를 채우고 오래된 것은 바로 대기
- 대기 카드는 버리지 않음. 카드가 닫혀 자리가 나면 **가장 최근에 빠진 카드부터**(나중에 들어간 것 먼저) 돌아오며, 보이는 카드보다 오래됐으므로 맨 아래에 놓임
- `+N건 대기` · **모두 확인**은 맨 아래 카드(대기 카드 바로 옆)에 표시. 모두 확인은 보이는 카드와 대기 카드를 모두 닫음
- 메뉴가 열린 카드는 빠지지 않음(메뉴가 닫힌 가장 오래된 카드가 대신 빠짐). 메뉴로 커진 카드 때문에 화면 높이를 넘으면 그만큼 오래된 카드가 대기
- 자동 닫기 타이머는 보이는 카드만 흐름. 대기 중에는 멈췄다가 다시 보일 때 처음부터
- 자동 닫기를 켜면 카드 아래 막대가 줄어들고, **마우스를 올리거나 자리 비움 중에는 멈춤**
- 포커스를 빼앗지 않는 창이라 입력 중인 작업을 방해하지 않음
