# 할 일·로컬 캘린더 연동 (#94)

> 소스 구현 기준: 연동에는 엔진 1.0.4 / API 1.6과 두레이·메일·할 일·캘린더 위젯을 함께 사용합니다. #108 동기화가 추가된 할 일·캘린더 위젯 테스트판의 최소 엔진 API는 1.8입니다. 실제 설치 환경의 장기 동작은 별도 확인 대상입니다.

## 사용 흐름

1. 두레이 업무나 메일에서 사용자가 **할 일에 추가**를 누릅니다. 제목과 출처 정보가 할 일 위젯에 복사됩니다. 두레이의 마감일은 후보 목표 날짜로 제시하고, 메일은 사용자가 목표 날짜를 지정할 수 있습니다.
2. 할 일에 완료 목표 날짜 또는 날짜·시각이 있으면 캘린더의 **할 일 마감** 표시로 나타납니다. 날짜가 없으면 캘린더에 표시하지 않습니다.
3. 사용자는 할 일 위젯뿐 아니라 캘린더에서도 할 일의 목표 날짜·시각을 수정할 수 있습니다. 캘린더의 변경은 할 일 원본에 전달하고, 저장된 현재 상태를 다시 읽어 반영합니다. 할 일을 삭제하거나 날짜를 옮기면 이전 날짜의 표시는 사라집니다. 재시작 후에도 저장된 할 일에서 다시 계산합니다.
4. 캘린더 설정에서 완료한 할 일을 **숨김** 또는 **완료 표시** 중 사용자가 선택합니다. 완료 표시를 선택하면 해당 날짜에 완료 상태를 구분해 표시합니다.
5. 캘린더에는 기본으로 켜진 **내 캘린더**를 추가해 사용자가 인터넷 없이 일반 일정을 만들고 수정·삭제할 수 있게 합니다. 로컬 일정은 캘린더 위젯의 데이터 폴더에 저장하며, CalDAV·ICS 일정과 함께 보되 외부 서버로 자동 전송하지 않습니다.

## 데이터 소유권과 동기화

### #108 엔진 동기화 폴더

엔진에서 동기화 폴더를 켜면 할 일 위젯은 목록과 할 일, 캘린더 위젯은 **내 캘린더** 일정과 CalDAV 계정 정보를 동기화합니다. 할 일 마감은 캘린더 일정으로 복사하지 않고 각 PC에서 할 일 원본으로부터 다시 표시합니다. 할 일의 알림을 이미 보여준 시각·다시 알림 시각, 창 위치, 선택한 목록, 두레이·메일 받기와 캘린더 공유 허용은 PC마다 따로 둡니다.

CalDAV의 암호와 계정 사용 여부는 각 PC에서 설정합니다. 새 PC로 들어온 계정은 꺼진 상태로 두고, 그 PC에서 암호를 입력한 뒤 사용자가 켭니다. ICS 구독 URL에는 비밀 토큰이 들어갈 수 있으므로 동기화하지 않습니다. 캘린더의 할 일·할 일 노트 연동 허용도 PC마다 따로 둡니다. 동기화 폴더에는 개인 일정과 할 일 내용이 평문으로 저장되므로 접근 권한이 있는 폴더를 선택해야 합니다. 자세한 충돌 처리와 폴더 구조는 [동기화 설계](cloud-sync-design.md)를 참고하세요.

| 데이터 | 단일 원본 | 캘린더 표시 |
|---|---|---|
| 일반 로컬 일정 | 캘린더 위젯의 로컬 일정 저장소 | 내 캘린더에서 읽고 편집 |
| 할 일 목표 날짜 | 할 일 위젯의 로컬 할 일 저장소 | 할 일 ID를 안정적인 표시 ID로 사용해 현재 상태를 투영 |
| 외부 일정 | 각 CalDAV 서버 또는 ICS 구독 | 기존 동작 유지 |

할 일 마감을 **두 번째 독립 일정으로 복사해 저장하지 않습니다.** 날짜 변경 알림을 받으면 캘린더가 할 일의 전체 스냅샷을 다시 읽고 표시를 조정합니다. 캘린더가 먼저 시작하거나 변경 알림을 놓친 경우에도 재시작·위젯 상태 변경 때 전체 스냅샷으로 맞춥니다. 동일한 할 일 ID의 이전 날짜 표시는 남지 않아야 합니다. 날짜만 있는 할 일은 PC의 현지 날짜에 종일 마감으로, 시각이 있는 할 일은 해당 시각의 마감으로 표시합니다. 목표 시각을 임의 길이의 일정으로 늘리지 않고 마감 표시로 구분합니다. 기존 할 일 저장값의 날짜 전용 플래그를 사용해 날짜가 하루 밀리지 않게 합니다.

캘린더에서 할 일 마감을 옮기거나 날짜·시각을 수정할 때도 엔진을 거쳐 할 일 위젯의 수정 동작을 호출합니다. 캘린더가 자기 저장소에 별도 변경값을 만들지 않습니다. 할 일 위젯의 저장이 성공한 뒤 새 스냅샷을 읽어 표시를 바꾸며, 저장에 실패하거나 할 일 위젯에 접근할 수 없으면 변경 전 표시를 유지하고 사용자에게 오류를 알립니다. 완료 항목 표시 설정은 캘린더의 표시 방식만 제어하고, 할 일의 완료 상태나 목표 날짜를 변경하지 않습니다.

두레이·메일에서 할 일로 추가하는 것은 **사용자 조작으로 시작하는 일회성 복사**입니다. 원본 업무나 메일이 이후 수정됐다는 이유만으로 사용자가 편집한 할 일을 덮어쓰지 않습니다. 출처 식별자와 다시 열기 정보는 보존하되, 메일 본문·첨부 파일이나 두레이 댓글을 자동 복사하지 않습니다. 원본 위젯이 꺼지거나 제거돼도 복사한 할 일은 유지합니다. 같은 원본을 다시 추가하면 출처 ID가 같은 기존 할 일을 반환하며 중복 생성하지 않습니다.

## 위젯 경계

현재 위젯은 각자 따로 설치되고 데이터 폴더도 분리됩니다. 다른 위젯의 파일을 직접 읽거나 모듈을 `require`하지 않고, 엔진이 허용한 호출과 변경 알림을 중개해야 합니다. 할 일 저장은 할 일 위젯만, 일반 로컬 일정 저장은 캘린더 위젯만 수행합니다. 캘린더는 할 일 마감 표시를 외부 CalDAV·ICS에 자동 기록하지 않습니다. 위젯이 미설치·중지·갱신 중인 경우를 구분해 조용히 데이터가 사라진 것처럼 보이지 않도록 상태를 설계합니다.

## 위젯별 연동 설정과 필요 조건

연동은 처음에 꺼져 있으며 사용자가 해당 위젯 설정에서 켭니다. 켜면 설정 화면에 필요한 조건과 현재 충족 상태를 보여줍니다. 위젯 설치·사용 상태, 엔진 버전과 위젯 간 전달 API 지원 여부, 상대 위젯의 연동 기능 지원 여부를 실제 상태로 검사하고, 조건이 부족하면 필요한 조치를 표시합니다. 조건이 부족해도 사용자의 켜기 선택은 보존하되 기능은 실행하지 않으며, 조건이 충족되면 다시 동작합니다. 사용자가 끄면 새 연동 호출과 할 일 마감 표시·캘린더 편집을 중단하고, 이미 저장된 할 일이나 로컬 일정은 지우지 않습니다.

| 위젯 설정 | 켜면 제공하는 기능 | 표시할 필요 조건 |
|---|---|---|
| 두레이: **할 일 연동** | 선택한 업무를 할 일에 추가 | 할 일 위젯 설치·사용, 할 일의 받기 허용, 호환되는 연동 기능, 이를 중개하는 엔진 |
| 메일: **할 일 연동** | 선택한 메일을 할 일에 추가 | 할 일 위젯 설치·사용, 할 일의 받기 허용, 호환되는 연동 기능, 이를 중개하는 엔진 |
| 할 일: **두레이에서 받기**, **메일에서 받기** | 각 출처의 추가 요청을 독립적으로 허용 | 해당 원본 위젯 설치·사용, 원본 위젯의 할 일 연동 켜짐, 호환되는 연동 기능, 이를 중개하는 엔진 |
| 할 일: **캘린더에 마감 표시** | 할 일 목표 날짜의 읽기·수정 요청을 캘린더에 허용 | 캘린더 위젯 설치·사용, 캘린더의 할 일 연동 켜짐, 호환되는 연동 기능, 이를 중개하는 엔진 |
| 캘린더: **할 일 연동** | 할 일 마감 표시와 캘린더에서 목표 날짜·시각 수정 | 할 일 위젯 설치·사용, 할 일의 캘린더 마감 표시 켜짐, 호환되는 연동 기능, 이를 중개하는 엔진 |

양쪽 위젯의 설정이 모두 켜지고 필요 조건이 충족되어야 해당 연동이 동작합니다. 한쪽을 끄면 상대 위젯에도 사용 불가 이유를 표시합니다. 캘린더에서 연동을 끄면 할 일 마감 표시만 사라지고 **내 캘린더**의 일반 일정과 CalDAV·ICS 표시는 유지합니다. 다시 켜면 할 일의 전체 스냅샷으로 복원합니다. 두레이·메일에서 이미 복사된 할 일은 어느 쪽을 꺼도 유지합니다. 완료 항목 숨김/완료 표시 옵션은 캘린더의 할 일 연동이 켜진 동안에만 적용합니다.

새 화면 문구는 한국어·영어로 번역하고, 필요 조건의 버전과 상태는 고정 문구가 아닌 엔진과 각 위젯의 메타데이터에서 읽습니다. 예를 들어 두레이에는 `할 일 연동 · 필요: 할 일 위젯 사용, 호환되는 엔진/연동 API`처럼 보여주되 실제 부족한 항목을 구분합니다. 연동 중개 기능은 **엔진 1.0.4 / API 1.6**에 추가됐으므로 **1.0.3 이상**이라는 조건만으로 사용 가능하다고 표시하지 않습니다. 상대 위젯은 필요한 연동 기능을 선언하고 양쪽 설정을 켜야 합니다.

## 구현 구성과 검증 항목

1. 엔진의 제한된 위젯 간 전달 계약, 기능·버전 조회와 설치·중지 상태 처리.
2. 네 위젯의 연동 설정과 필요 조건·현재 상태 표시를 추가. 양쪽 켜짐 조건, 조건 미충족·복구, 끈 뒤 기존 데이터 유지와 한국어·영어 문구를 검증.
3. 할 일에 출처 식별자·다시 열기 정보와 목표 날짜 편집을 추가하고, 두레이·메일에서 사용자 조작으로 추가.
4. 캘린더에 오프라인 **내 캘린더**와 일반 로컬 일정 편집을 추가.
5. 할 일 마감을 캘린더에 투영하고 캘린더의 날짜 편집을 할 일 원본에 전달. 날짜 이동·삭제·재시작·알림 누락·날짜 전용/시각 지정·시간대 경계·위젯 미설치·저장 실패·완료 항목 표시 옵션을 검증.

엔진의 위젯 간 호출은 허용된 방향과 메서드로 제한합니다. 각 위젯의 설정값은 해당 위젯 데이터에 남고, 로컬 캘린더 일정은 캘린더 위젯의 별도 저장 파일에 남습니다. 할 일 마감은 캘린더에 영구 일정으로 복사하지 않습니다.
