# 스티키 노트 위젯

바탕화면 스티키 노트입니다(#75, #95, 첫 정식 버전 1.0.0은 #100). 노트마다 작은 창이 하나씩 뜨고, 서식이 보이는 상태로 바로 고치며(WYSIWYG), 내용은 **문서 폴더의 Markdown(.md) 파일**로 저장됩니다.

> **할 일 노트로 합쳐졌습니다**(#110 계획대로 할 일 노트 정식 배포 뒤 적용, #117). 스티키 노트는 1.1.1에서 더 이상 새 버전이 나오지 않지만, 지금 버전은 계속 내려받아 쓸 수 있고 노트도 그대로입니다. 할 일 노트는 같은 Markdown 노트 파일을 쓰므로 노트 파일을 할 일 노트 폴더로 옮기면 그대로 열립니다([할 일 노트](todonote.md) "스티키 노트·할 일 목록에서 옮기기"). 두 위젯의 노트 폴더를 같은 폴더로 설정하지는 마세요.

## 1. 노트는 어디에 저장되나요

- 기본 폴더: `문서\Desk Widgets\스티키 노트` (설정 → 노트 폴더에서 바꿀 수 있음)
- 엔진 동기화를 켜도 노트 폴더는 바뀌지 않습니다. 노트는 항상 이 PC의 노트 폴더(문서 폴더 또는 고른 폴더)에 있고, 엔진이 그 변경을 동기화 폴더로 주고받습니다.
- 노트 하나 = `.md` 파일 하나. 파일 이름은 `20261027-093000-a1b2c3d4e5f6.md`처럼 **만든 때 + 노트 id**입니다(아래 "제목과 파일 이름"). 이미지·첨부 파일은 옆의 같은 이름 `.assets` 폴더에 들어가고, md 안에서는 `20261027-093000-a1b2c3d4e5f6.assets/그림.png` 같은 상대 경로로 이미지를 참조합니다(이미지 문법 `![설명](경로)`).
- 보관함으로 옮긴 노트는 같은 폴더의 `보관함` 하위 폴더로 갑니다(이미지 폴더도 함께).
- 파일 맨 위 머리말(front matter)에 위젯이 `title: 제목`, `created: 만든 때`, `desk-widgets-memo: <id>`를 씁니다. id는 다른 프로그램에서 파일 이름을 바꿔도 같은 노트로 알아보기 위한 값이고, 다른 프로그램이 쓴 머리말 줄은 그대로 둡니다. `.md`라 메모장·VS Code 같은 다른 편집기로도 열 수 있지만, 다른 프로그램과 함께 쓰는 것을 목표로 만들지는 않았습니다.

### 제목과 파일 이름 (#113)

- **제목은 머리말의 `title:`에만** 있고, 창 제목·목록·검색·`[[링크]]`·백링크가 모두 이 제목을 씁니다. **파일 이름은 저장용**이라 `YYYYMMDD-HHmmss-<노트 id>.md`(만든 때의 이 PC 시각)로 정해지고 **바뀌지 않습니다**. 같은 제목의 노트가 여러 개 있어도 됩니다.
- 이름을 바꾸면 머리말의 `title:`만 고칩니다. 파일·첨부 폴더·노트 안의 이미지 경로는 그대로입니다. 보관함으로 옮기거나 꺼낼 때도 같은 이름으로 폴더만 바뀝니다(그 폴더에 같은 이름의 다른 파일이 있을 때만 ` (2)`).
- 위젯이 만들지 않은 파일(탐색기에서 만든 `회의.md`, `.txt` 등)은 **파일 이름이 제목**이고 이름을 바꾸지 않습니다. 위젯이 그 노트를 저장하면 머리말에 id와 `title:`을 더하지만 파일 이름은 그대로입니다(`.txt`는 머리말이 없어 이름 바꾸기 때 파일 이름이 바뀝니다).
- **예전 판에서 업데이트하면 한 번 정리합니다**(노트 폴더마다 한 번, 폴더를 예전 노트가 있는 폴더로 바꿀 때도). 창을 열기 전에 위젯 id가 있는 노트를 **같은 폴더 안에서** id 이름으로 바꾸고, 첨부 폴더와 노트 안의 이미지 경로도 함께 고칩니다. 예전 노트는 두 PC가 똑같이 아는 만든 때가 없어(파일 시각은 PC마다 다름) 머리말에 `created:`가 없으면 `<노트 id>.md`가 됩니다. `title:`이 없으면 지금 보이는 제목을 적고, 예전 판이 이름이 겹쳐 붙인 번호는 뺍니다: `회의 (2)`는 같은 위젯에 `회의`나 `회의 (3)` 같은 노트가 있을 때만 제목이 `회의`가 되고, 그런 노트가 없거나 다른 노트가 `[[회의 (2)]]`로 가리키고 있으면(이름을 바꾼 뒤에는 제목으로만 찾을 수 있으므로) 그대로 둡니다. 다른 노트 안의 파일 경로 링크(`[글자](회의%20(2).md)`, `[글자](완료/보고서.md#소제목)`, 다른 노트의 첨부 이미지 `![](회의.assets/그림.png)`)도 새 파일 이름으로 고칩니다(위젯 id가 없는 파일 안의 링크도, 코드 안은 그대로). 노트 목록 위에 "노트 저장 방식이 바뀌어 기존 노트 N개의 파일 이름을 바꿨습니다. 제목과 내용은 그대로입니다."(번호를 뺀 노트가 있으면 "내용은 그대로이고, 제목 끝에 자동으로 붙었던 번호 K개만 뺐습니다.", 링크를 고친 노트가 있으면 "노트 M개 안의 파일 링크도 새 이름으로 고쳤습니다."가 더해짐)를 한 줄로 알립니다(묻는 창 없음). 고친 시각(목록 순서)은 그대로입니다. 위젯 id가 없는 파일은 이름과 머리말을 바꾸지 않고(링크만 고침), `.txt`·충돌 사본·5MB가 넘는 파일은 이름을 바꾸지 않습니다. 정리하지 못한 노트(다른 프로그램이 잡고 있는 파일, 새 이름이 이미 있는 경우 등)는 그대로 두고 그 이름을 알리며, 다음에 켤 때 다시 시도합니다. 지우는 것은 없습니다. 같은 폴더를 동기화하는 두 PC가 따로 정리해도 같은 파일 내용·이름이 되어 충돌이 생기지 않습니다. 정리했는지는 이 PC의 위젯 설정에만 적습니다.
- 탐색기에서는 파일 이름으로 노트를 알아볼 수 없습니다. 노트 창의 오른쪽 클릭 → **정보…** 에서 제목·파일 위치(복사 단추)·만든 때·바뀐 때·크기를 볼 수 있고, **탐색기에서 보기**로 그 파일을 찾아 줍니다. 다른 프로그램에서 파일 이름을 바꿔도 제목은 바뀌지 않습니다.
- 창 위치·크기·색·열림 여부·항상 위 같은 **화면 설정만** 위젯 설정 폴더(`%APPDATA%\chilgong88\desk-widgets\widgets\memo\settings.json`)에 있습니다.

**제거해도 노트는 남습니다.** 위젯 제거 프로그램은 설치 폴더(`C:\Program Files\chilgong88\widgets\memo`)와, 고르면 위젯 설정 폴더만 지우고, Desk Widgets 제거 프로그램은 `%APPDATA%\chilgong88\desk-widgets`만 지웁니다. 문서 폴더는 어느 쪽도 건드리지 않습니다. 그래서 설정에서 노트 폴더를 프로그램·설정 폴더 **안**으로 고르는 것은 막혀 있습니다.

### 이름이 "메모"에서 "스티키 노트"로 바뀌었습니다 (#95)

메모장과 헷갈리지 않도록 위젯 이름을 바꿨습니다(포스트잇은 3M 상표라 쓰지 않음). 처음 개발판(0.0.1, `MemoWidget`)을 쓰던 경우:

- **설치**: `DeskWidgets-StickyNoteWidget-Setup-0.0.1.exe`를 그냥 설치하면 됩니다. 제어판 항목은 위젯 id(memo)로 만들어지므로 예전 **Desk Widgets-MemoWidget** 항목이 **Desk Widgets-StickyNoteWidget**으로 바뀌고 따로 남지 않습니다. 설정·창 위치·색·열려 있던 노트는 그대로입니다.
- **노트 폴더**: 기본 폴더를 쓰던 경우에만, 업데이트 뒤 처음 켤 때 `문서\Desk Widgets\메모`를 `문서\Desk Widgets\스티키 노트`로 한 번 옮깁니다. 결과는 노트 목록 창 위쪽에 한 번 안내됩니다.
  - 보통은 폴더 이름만 바뀝니다(파일 복사 없음).
  - 예전 폴더의 파일이 사용 중이라(OneDrive 동기화, 다른 프로그램) 이름을 바꿀 수 없으면, 새 폴더로 복사해 모든 파일이 똑같은지 확인한 뒤 새 폴더를 씁니다. 예전 폴더는 지우지 않고 남기니, 새 폴더를 확인한 뒤 직접 지우면 됩니다.
  - 복사도 안 되면 예전 폴더를 계속 씁니다(설정의 노트 폴더에 예전 경로가 들어감).
  - 두 폴더 모두 파일이 있으면 **합치지 않고** 예전 폴더를 계속 씁니다. 설정에서 쓸 폴더를 고르세요.
  - 설정에서 다른 폴더를 직접 고른 경우는 아무것도 옮기지 않습니다.

| 서식 | 창 위 **Aa**로 서식 도구 보이기. 단축키 Ctrl+B 굵게, Ctrl+I 기울임, Ctrl+Shift+X 취소선, Ctrl+E 코드, Ctrl+K 링크 |

| 체크 목록 | 체크 칸을 누르면 완료/미완료 (파일에는 `- [x]` / `- [ ]`) |
| 목록 들여쓰기 | Tab / Shift+Tab |
| 줄 바꿈 | Enter는 새 문단, Shift+Enter는 같은 문단 안에서 줄 바꿈 |

| 이름 | 처음 쓴 줄이 노트 제목이 됩니다(창에서 나가거나 닫을 때, 파일 이름은 그대로). 오른쪽 클릭 → 이름 바꾸기로 직접 정하면 그 뒤로는 자동으로 바뀌지 않습니다 |

저장은 자동입니다. 쓰는 동안 잠깐 멈추면(약 0.6초, 계속 쓰더라도 3초 안에) 저장되고, 위젯을 끄거나 Desk Widgets를 종료할 때도 남은 내용을 저장합니다. 파일은 임시 파일에 쓴 뒤 바꿔 넣으므로 저장 중에 꺼져도 반쯤 쓰인 파일이 남지 않습니다.

### 노트끼리 연결 (`[[ ]]`)

- `[[`를 입력하면 노트 이름 목록이 뜹니다. 글자를 더 치면 좁혀지고, ↑↓로 고른 뒤 Enter나 Tab으로 넣습니다(Esc 닫기). 목록에 없는 이름이면 맨 아래 **새 노트 만들기: 이름**으로 링크만 넣어 둘 수 있습니다.
- `[[이름]]`처럼 닫는 괄호까지 직접 쳐도 링크가 됩니다. `[[이름|보이는 글자]]`(다른 글자로 보이기), `[[이름#소제목]]`도 됩니다. 링크의 글자를 고치면 파일에는 `[[이름|고친 글자]]`로 저장됩니다.
- **Ctrl+클릭**하면 그 노트 창이 열립니다. 아직 없는 노트(점선으로 흐리게 보임)는 그 이름으로 새로 만들어 엽니다. 보관함에 있는 노트는 열지 않고 꺼내라고 안내합니다.
- 노트는 **제목으로** 찾고(대소문자 구분 없음), 그 제목의 노트가 없으면 **파일 이름으로** 찾습니다(손으로 쓴 파일 이름 링크). 파일에는 `[[이름]]` 글자 그대로 저장됩니다. `[글자](파일 이름.md)` 형식의 링크도 같은 노트 링크로 셉니다.
- **같은 제목의 노트가 여럿이면**(#113) 열 수 있는 노트 → 충돌 사본 → 보관함 순으로, 같은 쪽 안에서는 **가장 최근에 고친 노트**를 엽니다. 백링크는 링크가 실제로 가리키는 노트에만 보입니다.
- 노트 **이름을 바꾸면**(직접 바꾸든 첫 줄로 자동으로 바뀌든) 다른 노트 안의 `[[옛 이름]]`·`[[옛 이름|글자]]`·`[[옛 이름#소제목]]`도 새 이름으로 고쳐집니다(보관함 노트 포함, 코드 안은 그대로). 고친 노트 수가 창 아래에 잠깐 표시됩니다. `[[옛 제목]]`이 같은 제목의 **다른** 노트를 가리키고 있었다면 그 링크는 그대로 둡니다. 파일 이름은 바뀌지 않으므로 파일 이름 링크도 그대로 맞습니다(#113).
- **노트 목록**에는 노트마다 그 노트를 가리키는 노트(백링크)가 `← 할 일, 일기`처럼 표시되고, 이름을 누르면 그 노트가 열립니다.

## 3. 창과 메뉴

- 위쪽 띠를 끌어 옮기고, 가장자리를 끌어 크기를 바꿉니다. **▾** 접기(띠만 남음), **×** 창 닫기(노트는 목록에 남음). 아무것도 쓰지 않은 새 노트를 닫으면 빈 파일은 지워집니다.
- 오른쪽 클릭: 잘라내기·복사·붙여넣기(글 위에서), 새 노트, 노트 목록, **항상 위에 표시**, **색**(미드나잇 글래스·노랑·분홍·파랑·초록·보라·회색·어두운 색), 접기, 이름 바꾸기, **정보…**(제목·파일 위치와 복사 단추·만든 때·바뀐 때·크기, 창 안의 작은 판, Esc로 닫기), 탐색기에서 보기, 보관함으로 옮기기, 휴지통으로 옮기기(확인 후, 휴지통에서 되살릴 수 있음), 노트 닫기, 그리고 다른 위젯과 같은 설정·위젯 관리·끄기·종료.
- Win+D를 눌러도 다른 위젯처럼 바탕화면에 남습니다(엔진의 바탕화면 고정 설정을 따름).
- 위젯을 다시 켜면 열려 있던 노트 창이 같은 자리·크기·색으로 돌아옵니다.

## 4. 노트 목록

목록 창(오른쪽 클릭 → 노트 목록, 또는 위젯 관리에서 위젯 이름을 누름): 검색(제목·내용), 새 노트, 누르면 열기, 📌 목록 맨 위 고정, ⊟ 창 닫기, 🗄 보관함으로, 🗑 휴지통으로. **보관함** 탭에서 ↩로 꺼냅니다. 📁은 노트 폴더를 탐색기로 엽니다. ● 표시는 지금 창이 열려 있는 노트입니다.

## 5. 다른 프로그램과 함께 쓰기

- 노트 폴더를 감시합니다. 메모장 같은 다른 편집기에서 고친 내용은 열린 노트 창에 바로 보입니다.
- 노트 창에 **아직 저장하지 않은 내용**이 있을 때 파일이 바깥에서 바뀌면 덮어쓰지 않고 고르게 합니다: **바뀐 내용 보기**(바깥 것을 보이고 내 것은 버림) / **내 내용으로 저장**(내 것으로 덮어씀) / **내 내용은 사본으로**(`제목 (내 사본).md`로 따로 저장하고 바깥 것을 보임). 고르기 전에 위젯을 끄면 내 내용은 사본 파일로 저장됩니다.
- 열린 노트의 파일이 지워지거나 옮겨지면 "노트 파일이 없어졌습니다"가 뜨고, 다시 저장하거나 창을 닫을 수 있습니다. 다른 프로그램에서 이름만 바꾼 경우는 머리말의 id로 따라갑니다.
- **OneDrive 충돌 사본**(`제목-PC이름.md`처럼 같은 id가 든 파일이 하나 더 생김): 원래 파일이 그 노트로 남고, 다른 쪽은 목록에 **충돌 사본**으로 표시됩니다. 열어서 비교한 뒤 필요 없는 쪽을 휴지통으로 옮기세요. 사본을 고쳐 저장하면 그 사본은 새 id를 받아 별도 노트가 됩니다.

## 6. 예전 .txt 노트

노트 폴더의 `.txt` 파일도 목록에 나오고 열립니다. 이때는 **글자만 고치는 모드**(서식·이미지 없음)이고 저장도 .txt 그대로입니다. 오른쪽 클릭 → **Markdown 노트로 바꾸기**를 누르면 같은 이름의 `.md`를 만들고(모든 줄을 글자 그대로 옮김), 원래 `.txt`는 지우지 않고 `보관함` 폴더로 옮깁니다. 다른 곳의 .txt를 가져오려면 노트 폴더에 복사해 넣으면 됩니다.

## 7. 설정

- **노트 폴더**: 폴더 고르기·기본 폴더로·폴더 열기. 폴더를 바꾸면 **"기존 노트를 새 폴더로 옮길까요?"** 를 묻습니다(#108). **옮기기**: 노트(.md·.txt), 첨부 폴더(파일 이름.assets), 보관함 폴더의 노트를 새 폴더로 복사하고 내용을 바이트 단위로 확인한 뒤 원래 파일을 **휴지통**으로 보냅니다(되살릴 수 있음, "옮긴 뒤에도 원래 폴더에 파일 남기기"를 켜면 남김). 노트가 아닌 다른 파일은 옮기지 않습니다. 새 폴더에 같은 이름의 노트가 있으면, 첨부가 없는 노트는 파일 이름만 "제목 (2)"로 옮기고(제목은 그대로), 첨부가 있는 노트는 이미지 연결이 깨지므로 **아무것도 옮기지 않고** 그 이름을 알려 줍니다. 복사가 하나라도 실패하면 만든 사본을 지우고 폴더도 바꾸지 않습니다. 옮긴 결과는 목록 창 위에 한 줄로 알려 줍니다. **옮기지 않기**: 새 폴더의 노트를 보여 주고 원래 폴더는 그대로 둡니다. **취소**: 폴더를 바꾸지 않습니다. 동기화 중에는 어느 쪽이든 다른 PC의 노트가 지워지지 않습니다. 엔진이 폴더가 바뀐 것을 알아보고 그 노트 저장소를 처음 연결처럼 다시 맞추기 때문에, 새 폴더에 없는 노트는 삭제로 보내지 않고 다른 PC에서 받아옵니다.
- **새 노트 색**, **글자 크기**(10~24), **배경 불투명도**(배경에만 적용, 글자는 그대로 — 다른 위젯과 같은 방식). 새 노트의 기본 색은 **노랑**입니다. 어두운 화면에 어울리는 **미드나잇 글래스**는 새 노트 색 설정이나 노트 창의 오른쪽 클릭 → 색에서 선택할 수 있습니다. 1.1.1-test.3에서 새 노트 색이 미드나잇 글래스로 저장됐다면 이번 버전에서 노랑으로 돌아갑니다. 계속 미드나잇을 쓰려면 설정에서 다시 선택하세요. 이미 만든 노트의 색은 유지됩니다.

## 8. 안전

- 노트 창은 위젯이 만든 정리된 HTML만 보여 줍니다(허용 목록 방식: 스크립트·iframe·이벤트 속성·style 없음). 파일 안의 HTML 태그는 실행되지 않고 **글자 그대로** 보이며 그대로 저장됩니다.
- 이미지는 **그 노트의 폴더 안 파일만** 위젯이 읽어서 보여 줍니다(8MB까지, 더 크면 자리 표시만). 인터넷 주소의 이미지는 불러오지 않습니다(창의 보안 정책이 외부 요청을 막음).
- 링크는 http·https·mailto만 브라우저로 열고, 첨부 파일은 그 노트의 `.assets` 폴더 안의 것만 엽니다.

## 9. 알려진 제한 (0.0.1)

- 지원하는 Markdown: 제목, 굵게·기울임·취소선, 인라인 코드, 코드 블록, 글머리·번호·체크 목록(중첩), 인용, 링크, 노트 링크 `[[ ]]`, 가로줄, 표(기본), 이미지. 그 밖의 것(각주, 수식, 참조식 링크 `[a][1]`, HTML 태그, 밑줄)은 글자로 보입니다.
- 위젯에서 한 번 고치면 파일 표기가 정리됩니다: `*`/`_` → `**굵게**`·`*기울임*`, `* 목록` → `- 목록`, 번호 다시 매김, 밑줄 제목(`===`) → `#`, 줄 앞 공백 제거, 연속 빈 줄 하나로(빈 줄 하나를 남기려고 쓴 빈 문단은 `&nbsp;`로 저장). 고치지 않은 노트 파일은 열기만 해서는 바뀌지 않습니다.
- 한 줄 바꿈(Enter 없이 이어진 줄)은 줄 바꿈으로 보입니다(다른 Markdown 보기 프로그램은 한 문단으로 합칠 수 있음).
- 표 칸 안의 줄 바꿈은 저장 시 띄어쓰기가 됩니다. 표에 줄·칸을 더하는 버튼은 아직 없습니다(처음 2×2, 칸 안에서 Tab 이동 없음).
- 붙여넣기는 글자만(다른 문서의 서식은 들어오지 않음). 노트 사이 복사도 서식 없이 됩니다.
- 이미지 크기 조절은 없습니다(창 너비에 맞춰 보임). 바깥 변경을 불러오면 실행 취소(Ctrl+Z) 기록이 지워집니다.
- 위젯이 이름을 붙이지 않은(머리말 id가 없는) `.md`·`.txt`는 다른 프로그램에서 이름을 바꾸면 새 노트로 보여 창 위치·색을 잃습니다(위젯에서 한 번 고치면 id가 생김).
- 같은 폴더의 하위 폴더(`보관함` 말고)에 있는 노트는 목록에 나오지 않습니다.
- 강제 종료(작업 관리자 등)나 정전 때는 마지막 0.2~3초 동안 쓴 내용이 저장되지 않을 수 있습니다.
- 5MB가 넘는 노트 파일은 목록에만 나오고 열리지 않습니다.
- `[[ ]]` 링크: 제목이 같은 노트가 여럿이면 보관함 밖의 것, 그중 가장 최근에 고친 것을 엽니다(2장). `![[그림]]`(Obsidian 끼워 넣기)은 그림이 아니라 링크로 보입니다. 이름 바꾸기로 고칠 때, 그 순간 막 친 글자를 아직 보내지 않은 열린 노트(0.2초 이내)는 건너뜁니다. 새 노트를 만들거나 이름을 바꾸면 이미 열린 다른 노트 창의 "없는 노트" 점선 표시는 그 창을 다시 열 때 바뀝니다. 다른 프로그램에서 이름을 바꾼 경우에는 링크를 고치지 않습니다.

## 10. 사용한 라이브러리

없습니다. Markdown 해석·변환(`lib/markdown.js`)과 HTML 정리기(`lib/html.js`)는 이 위젯을 위해 직접 작성했습니다(위젯 패키지에는 node_modules가 없음, #40). 외부 라이선스 고지 대상이 없습니다.

## 11. 구조 (개발자용)

| 파일 | 역할 |
|---|---|
| `index.js` | 창·메뉴·설정·IPC(`memo-widget` 채널 하나, 보낸 창으로 노트를 구분) |
| `lib/library.js` | 노트 폴더: 목록·id·이름 바꾸기·보관함·휴지통·.txt 바꾸기·assets 복사와 경로 검사 |
| `lib/session.js` | 열린 노트 하나: 저장 지연·원자적 쓰기·바깥 변경/충돌·종료 시 저장 |
| `lib/markdown.js` | Markdown ↔ 편집기 HTML(트리) |
| `lib/html.js` | HTML 해석기와 허용 목록 정리기 |
| `lib/files.js` | 파일 이름 규칙·원자적 쓰기 |
| `memo/`, `list/`, `preload.js` | 노트 창·목록 창 화면(위젯 자체 페이지) |

**창 방식 결정**: 엔진 테마 호스트(`ctx.useThemes`)는 프레임별 여러 창(`openFrame(frame, instanceId)`)을 열 수 있지만, 노트 창에는 맞지 않아 **위젯 자체 창**(`ctx.createWidgetWindow`)을 씁니다. 이유: 테마 호출 인자가 64KB로 제한되어 붙여넣은 이미지를 보낼 수 없음, 격리된 테마 페이지에서는 끌어다 놓은 파일의 경로를 얻을 수 없음, 주 창(목록)을 닫으면 위젯이 꺼짐, 위젯 쪽에서 다른 프레임 창을 닫거나 항상 위를 바꾸는 API가 없음. 그래서 받은 테마는 없고(테마 규격 없음), 색 7가지와 배경 불투명도는 위젯 설정으로 둡니다.

**한 프로세스 (#109)**: 엔진에 `ctx.createSharedWidgetWindow`가 있으면 노트 창과 목록 창이 **렌더러 프로세스 하나를 같이 씁니다**(노트 1장당 약 16 MB → 약 2 MB, [메모리 사용량 점검](memory-review.md)). 창은 조금 뒤에 생기므로 그 사이에 보낸 내용은 버리고, 페이지가 열리며 `init`으로 받아 갑니다. 그 프로세스가 죽으면 모든 노트가 함께 비므로, 위젯이 페이지가 보낸 내용을 저장하고 노트와 목록을 같은 자리에 다시 엽니다(1분에 3번까지, 그보다 잦으면 다음 시작 때). 죽기 직전 아직 보내지 않은 몇 글자는 잃을 수 있습니다(따로 쓰는 창이 죽을 때와 같음). 없는 엔진에서는 예전처럼 노트마다 창(프로세스) 하나입니다.

**이미지 보여 주기**: 노트 창은 `img-src data:`만 허용합니다. 위젯 메인 코드가 그 노트 폴더 안의 이미지 파일을 읽어 data URL(8MB까지, 메모리 캐시 48MB)로 HTML에 넣고, 페이지는 저장할 때 `data-asset`(파일 이름)만 돌려보내므로 data URL이 파일에 들어가지 않습니다. 엔진 변경 없이 되고, 외부 주소·다른 폴더 파일을 불러올 수 없습니다.

## 12. 엔진 동기화 폴더 (#108)

엔진 1.1.1(API 1.8)부터 엔진의 동기화 폴더를 켜면 `.md`·`.txt` 노트와 같은 이름의 `.assets` 첨부 파일, `보관함`의 노트를 함께 동기화합니다. 노트별 색과 새 노트의 색·글자 크기·불투명도도 공유합니다. 창 위치·열림·고정 상태는 PC마다 따로 둡니다. 노트 폴더는 이 PC의 폴더 그대로이며, 엔진의 파일 저장소가 그 폴더를 감시하고 다른 PC와 주고받습니다(위젯은 동기화 폴더를 모릅니다). 저장 중인 글은 동기화 전에 파일에 기록하고, 받은 노트를 쓴 뒤에는 폴더를 다시 읽습니다. 받은 노트가 덮어쓰거나 지운 이전 파일은 노트 폴더의 `.sync-removed`에 30일 남습니다.

노트 폴더가 동기화 폴더와 겹칠 때만(그 안이거나 그 폴더를 품을 때) 엔진이 노트 파일을 주고받지 않습니다. 문서 폴더를 OneDrive로 백업해 노트 폴더가 OneDrive 안에 있어도 주고받습니다(현장 테스트: 그 경우를 건너뛰어 나중에 연결한 PC에 노트가 오지 않았음). 파일 하나의 동기화 한도는 20MB이므로 그보다 큰 첨부 파일은 다른 PC로 보내지 않습니다. 동기화 폴더의 접근 권한이 있는 사람은 노트 내용을 볼 수 있습니다.
