# 두레이·메일 데이터 폴더 동기화 (#108)

두 위젯의 분류·조건 알림 규칙·주소록은 엔진의 **항목 저장소**(`ctx.createStore`)에 있습니다. 파일은 예전과 같은 이 PC의 위젯 데이터 폴더(`categories.json`, `rules.json`, `contacts.json`)이고, 위젯은 동기화 폴더를 알지 못합니다. 위젯 관리 창에서 각 위젯 동기화를 직접 켜야 하며, 두레이·메일은 기본적으로 꺼져 있습니다. 켜면 엔진이 공유 표시된 필드의 사본을 사용자가 고른 폴더에 평문 JSON으로 씁니다. 업무 제목, 메일 제목, 메일 주소 등 업무 데이터가 들어가므로 회사 정책을 확인하고 켜야 합니다.

| 위젯 | 공유하는 데이터(필드) | PC에만 남기는 데이터 |
|---|---|---|
| 두레이 | 분류(이름·색), 업무별 분류 지정(분류 id·업무 사본·추가 시각), 조건 알림 규칙 | API 토큰(비밀 저장), 규칙 켜짐 상태, 규칙의 하루 확인 상태, 할 일 연동 스위치 |
| 메일 | 분류(이름·색), 메일별 분류 지정(분류 id·제목), 주소록의 주소·이름·가져옴·고침 표시 | 계정 비밀번호(비밀 저장), 메일 캐시, 지정 시각, 주소록 사용 횟수·마지막 사용, 학습한 메일 목록, 지운 주소 목록, 할 일 연동 스위치 |

다른 PC에서 처음 받은 두레이 조건 알림 규칙은 꺼진 상태로 저장됩니다. 이미 있는 규칙을 받아 고칠 때는 이 PC의 켜짐 상태를 유지합니다. 충돌과 삭제는 엔진의 항목 단위 비교 규칙을 따르고, 사용자에게 보이는 변경은 위젯 관리 창의 비교 화면에서 확인합니다. 다른 PC에서 지운 주소는 이 PC의 "지운 주소" 목록에 들어가지 않으므로, 그 주소에서 메일을 다시 받으면 주소록이 다시 배울 수 있습니다.

1.1.3-test 판이 동기화 폴더의 `widgets\dooray\<이 PC id>\`·`widgets\mail\<이 PC id>\`에 직접 쓰던 파일은 엔진이 처음 시작할 때 확인·백업한 뒤 이 PC의 파일로 되돌립니다(원본은 남김, [동기화 설계](cloud-sync-design.md) 10.5).

내부 테스트에는 서로 다른 두 Windows PC에서 분류·규칙·연락처 변경 및 삭제, 오프라인 상태에서 양쪽 수정, 토큰·비밀번호가 클라우드 폴더에 없는지 확인하는 과정이 필요합니다.
